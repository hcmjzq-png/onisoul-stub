原表 `skill.json`、`skillMessage.json` 提供技能 ID、效果、适用玩法和发动率。测试卡的技能按 G2、G4、G6 开眼，等级取原表 `changeLevel`，发动仍由既有结算器判定。五将用原表基础攻防智，品阶按测试所需开眼数配置。编队脚本只向新建的本地测试角色发卡，随后调用 `deck/setDecks` 写入 `quest.0`。国技「專用技解禁【攻】」的等级条件和装备技「無刀之極意」留待对应业务验证。测试队用三阵营条件的「紫陽花【壹】」提供暴击率。

卡名、阵营取 `character.json`、`item01.json` 与 `item01Message.json`。图册立绘按截图形象比对，山科那奈与千於銀按用户指示选普通版；图册编号与原始 PC 包的品阶映射未经确认。大立绘保留源图像素，小图使用同一立绘缩放，技能牌使用新绘的「本地测试」标签。发布清单留在本机，五个武将包和九个技能包的名称、纹理尺寸和 RGBA 像素经 UnityPy 读回校验。`assets` 和 `assets2` 两条路径对 14 个包均返回 HTTP 200，响应摘要与当前发布文件一致。初次临时卡牌替换前核对了本轮旧摘要。

## 当前测试角色补发与编成验收

本机运行目录源码为 `30c98be` 及已有改动，健康检查标签仍为 `local-story-tutorial-battle-c4092c6`。PC 当次登录的 `getPlayerParams` 与 MySQL 对上同一个角色。补发前，`common/getCharacters` 返回 8 张，五将只存在独立测试档。通过本地测试专用发卡工具，在一个锁定事务中添加 5 张武将卡。重复运行添加 0 张。MySQL 与当前客户端会话的 `common/getCharacters` 均为 13 张，`common/getSelectCharacters` 回读五将九技，已有 8 张及原编队前后相同。私有备份保留补发前的卡档与编队。

实际打开编成后，数量为 13，卡片详情可读到技能。此时发现上一版缩略图把立绘放在填充区，客户端只显示立绘一角。按现有 PC 模板核对三种有效区域为左上 75×100、120×160、180×240，重做同一素材的小卡和详情卡，战斗大立绘沿用源像素。五个更新包均按本轮旧摘要替换，`assets` 和 `assets2` 两条路径返回 HTTP 200 并与发布摘要吻合。卡档存于服务端，本轮使用既有客户端完成刷新。31 项编成、发技和恶鬼处理回归通过。

初次重登仍命中本地客户端的持久缓存。核对五条缓存内的资源 URL 与旧包完整 SHA-256 后，把这五条旧记录移入私有备份。21:09:56，从本地测试入口重登同一角色并打开编成，首屏显示五张新卡的完整小图，千葉伊勢详情显示三项技能。客户端新下载的五个包与发布摘要逐一相符。客户端程序及脚本均无本轮改动。下一步在鬼物语栏位配队后试打普通恶鬼。
