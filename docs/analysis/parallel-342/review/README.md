## 已修正和阻止接入的问题

1. **[P1，已修正] H 的设置数据可令原客户端类型转换失败。**
   原代码接受 `{"battle":{}}` 和 `{"potion":{"PoliticPotion":"yes"}}`，本次复现均返回成功并原样持久化。
   `PluginBattleSetting.cs:218-224` 无条件读取 `DreamSpaceType.GetType()`，并将其解析为
   `PluginMisc.getDreamSpaceName()` 的数组索引（该数组长度 2）。`HashAccessor.cs:29-87`
   对已存在字段做强类型转换，字符串不能作 bool。
   修正为原客户端字段名及类型校验，允许原版数值/字符串两种 0/1 梦幻空间索引；拒绝缺失、越界及错误类型。
   读存档也执行校验，坏档明确失败且不被静默覆盖。新增回归测试。
   设置接口仍未挂载：时长权益生产者未实现，类型修正不等于挂机业务完成。

2. **[P1，暂缓] 21 个组件没有完整接入前置条件。**
   B 的 `adventureV1`、D 的 `ResourceSnapshot`、F 的存活观测、G 的 `SnapshotPair`
   是服务端内部设计，并非恢复出的原服状态协议；当前没有可信生产端。
   E 的原子双账号适配器只在测试内存中实现，没有真实数据库实现；单玩家锁不能替代它。
   本次注册白名单只选择已具备状态来源的 8 项，其余 21 项仍由原占位处理器承接。
   对这些占位的响应不能视为真实业务成功；本轮没有统一改写全部占位失败策略。

3. **[P2，暂缓] A 背景切换地图编号与原 UI 不一致。**
   `mypageBgSelectWindow.cs:133-140` 固定传 `mapId=1`，A 组件仅接受 0；
   此外背景归属和 `getMapData` 的背景回读尚未接入。
   因支城实现属于用户警示的争议范围，不擅自把 1 映射成 0，不挂载这两个入口。

4. **[P2，暂缓] E 的过期申请可使整份申请状态读取失败。**
   现实现发现任何过期 `socialOffers` 就拒绝，而非原子清理申请双方记录。
   接入前必须补双边过期清理、拒绝/取消/解除后的周期通知映射，以及并发回滚验证。

5. **[P2，部分修正/待后续] 公共响应契约存在旧证据误分类。**
   已把 `politic/lottery/getSouls` 纳入公共裸映射规则：`onikujiWork.cs:199-206`
   遍历根值并强转 double，不能附加布尔 `succeeded`。
   `trophy/getTrophyProgress` 的现有 SCALAR_ROOT 记录则与 `TrophyWindow.cs:82-93`
   的根记录循环不符，至少 `access=mypage` 应为记录映射。其他 access 包装需要一起核实，
   本轮未全局改形状，也未挂载成就业务。D 的拍卖裸映射建议等留待对应模块接入时复核，
   不因字段同名批量修改所有端点。
