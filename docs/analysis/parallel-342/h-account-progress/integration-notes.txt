2. 存档/锁/事务
accountProgress 为新增内部存档命名空间，绝不直接返回此根键：
pluginSetting -> 回包 pluginData；pluginExpiresAt -> pluginTime.pluginTime；pluginLogs -> logdatas；pluginLogSequence 为内部单调序号。
PlayerServices.call + GameplayService._guard/_save 保持既有锁和存档机制；单玩家变更先校验后修改。
当前 _prepare_state 会保留未知字段，测试已验证跨重新登录保留；无需改公共默认状态。缺字段读空设置/空日志/零时长是兼容策略，不是原服初值。
时长只能由后续可信购买事务或有证据的迁移写入。H 没有任何发放时长入口；不要为了让设置可写而给新角色免费时长。
设置接口仅存储三类扁平标量参数，不解释、不运行、不校验每个业务任务的地图/物品合法性；执行入口必须各自校验归属/费用，不信任这些参数。
设置替换重试幂等，过期后重试会拒绝但不改原存档；日志无 nonce，重试会追加诊断条目，不承诺去重。
日志 reward 仅诊断文字/数量，不能计入资源、收藏、成就、任务或战绩。服务器覆盖 time，最近200条保留/大小限额为本服务策略。
多进程仍依赖现有存储 revision CAS；本分支测试注入 StateConflictError 验证失败不落档，没有伪称实测 DB 跨进程事务。
兑换码全局限额、迁居国家计数、其他跨账号事务未实现，不能用单玩家锁替代 DB 原子提交。

5. 最小独占动态验证（总集成安排，本分支没有启动客户端）
沿客户端→hosts→proxy80→stub 保存脱敏请求、原始响应、调用前后状态。模拟服输出只验兼容，不是原版规则证据。
- 引导前 getRevisions：四个 revision 与真实资源请求 URL 对齐；不得以改版本掩盖资源缺失。
- 可信有效时长账号：打开插件设置，改一项，重开/重登；过期账号同请求不写档；日志显示时间/顺序及重复请求行为。
- 印章：原服或可靠历史样本同日首次/重复、跨日、断签、重登；收集排期和奖品目录，勿假造日期。
- 每日/消耗/成就：一个真实事件前后、费用不足、重复领取、跨日、重登；同时获取服务端目录/概率/事件计数来源。
- 收藏：取得一件、凑齐、首次领取、重复领取后 item/payableCount/receiveCount 对照，确认分页起点。
- 迁居：先只读预检，不执行迁居；需要完整保留清单与可回滚隔离账号后才进行。
本机与局域网分别记录路由；H 不改 hosts/proxy80/config.ini，不部署服务器、不改变游戏尺寸或监控 UI。
