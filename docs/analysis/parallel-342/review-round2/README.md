## 主要问题及修正

1. **[P1，已修] B 障碍重试重复应用客户端扣费增量。**
   `clearObstacle` 保存只扣一次，但每次重试回放相同成功 uses。
   `QuestScriptCommand.cs:2189-2232,2287-2289` 对成功回包再次减资源。
   复现：初始 1500、费用 1000，两次调用后服务端 500，按原消费者执行两次成功回调后显示 -500。
   现已解除的重复请求返回 errorReason，不再重放四资源扣费量；并发仅首次成功。
   这是一项明确的模拟服兼容决策，丢失首次回包后仍须重新读取权威资源/进度，未声称恢复原服重试协议。
   原有收据继续用于拦截同区域新实例被旧请求误扣，不开放事件轮回。

2. **[P1，暂缓] A/D 的背景归属尚未贯通。**
   D 购买写 `items[itemId]=1`；A 的 `backgrounds/selected_background` 仍读 `backgroundOwnership`。
   因此“购买成功即可选择”的说法不成立，D 注释已纠正。还缺旧档归属迁移、默认/期限政策和
   原 UI `mapId=1` 与 A 支持 0 的解释。两边单测通过不能代替跨模块闭环。

3. **[P1，已处理] C/H 注册冲突可能丢失上轮白名单。**
   保留可选 `apis` 参数；H 委托成就注册时也传递该白名单。
   正常 `GameplayService` 不会因合入 H 组件自动开放成就领奖。
   回归明确验证新增 13 项及内部战术出售仍由原占位入口承接。

4. **[P2，已修] F 历史 rate 的精度验证与原消费者不一致。**
   `HTMLStrategyMatchMediator_History.cs:237-239` 经 `HashAccessFuncs.getInt` 先转 float32 再转 Int32。
   原候选接受 16777217、2147483647 等值，前者显示为 16777216，后者在转换时越界。
   投影现拒绝不可精确表示的数据，不修改权威值；覆盖正负边界及只读不改档。
   这是支持范围约束，不能据此推断原服战绩上限。G 同类石高检查的原源码链已独立复核。

5. **[P1，暂缓] 新组件依赖尚未变成真实生产能力。**
   B 的遭遇生产/活动授权、C 的可信 operation_id、D 的国力/周期上下文、E 的包裹发行和好友双账号事务、
   F/G 的真实战况/统计来源仍缺失。不得将测试中的 True、固定周期或人工快照复制进正式服务。
   E 对过期申请仍明确拒绝，已增加坏时间戳保护，但过期清理和通知尚未实现，不能关闭上轮阻塞项。
