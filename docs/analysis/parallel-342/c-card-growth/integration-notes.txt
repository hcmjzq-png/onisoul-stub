10. 本次追加：战术出售内部事务入口（不直接挂HTTP）
CardGrowthServices(service).sell_tactics_with_receipt(params, authenticated_session, operation_id=trusted_id)
内部自行调用 service._guard 和 PlayerServices.call；调用方不得再绕过会话认证。
params只沿用原tactics:<cardId,数量>，operation_id是内部调用参数，不是原协议字段。
只允许可信上层提供同一意图跨重试稳定、不同意图不复用的ID；禁止从请求正文、会话token、
参数散列、秒级时间窗生成。原客户端 WebApiClient.sendRequest 自动重发同一form，
没有上传httpCallId；目前服务路由也没有可信操作ID，故本分支register不挂sellTactics。
不允许用新随机ID包装每次HTTP重试来声称去重。缺可信ID前只能保留待集成状态。
必须由总集成先落实端到端的意图区分/标识获取，不能单凭本模块就完成原版HTTP对接。

cardGrowthTacticSales是本服内部玩家文档字段：SHA256(operation_id) -> quantities/payload。
与战术余额和gold一次保存，不回传为协议字段。相同ID/数量重放原业务回包；相同ID不同数量失败。
新ID允许相同数量的新交易。响应tactics是售出量，客户端自行扣减；回放只适用于同一次未完成请求，
不能作为新UI点击的成功回包，否则客户端会重复显示加钱。
无TTL、不静默淘汰收据；1024条后拒绝新交易（本服支持上限，不是原版限制），旧收据仍可重放。
正式长期运行需事务化收据归档/独立持久账本，保持历史ID不重新执行；不自动迁移现有档。
战术零余额保留原行，仅amount=0，现有查询及profile按余额读取。
保守拒绝六组编队引用的战术、金币溢出、数量不足、未知类型，整批无部分结算。
两服务实例CAS冲突测试用隔离内存CAS模拟，不等于验证真实MySQL；原状态适配器已具有revision事务。
仍需D组挂牌锁/托管库存协调；本代码不声称解决auction并发。
