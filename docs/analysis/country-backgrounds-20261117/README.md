2026-11-18：本地 47 国 v2 已完成结构和 HTTP 校验；用户已确认纪伊改善并恢复云端发布授权。
本轮代码、资源与服务同步结果见 [整合发布记录](../environment-background-release-20261118/README.md)。
这是 46 国自制背景＋37 国原版保留，不是缺失原版资源的恢复。

## 请求与缺失定位

原表 `country_setting.<country>.backdrop` 给出 pbmNN，初始 30×30 主城请求
`pbmNN_01`，资源文件名为其 UTF-16LE 名称的 MD5，分类为 pbm。
例如纪伊 country30 的资源键为 `6cc5a4bde052efab7c267aa6149da217`。
实际链路中 auth/createPlayer 成功，随后该背景连续 HTTP 404，属于
**stub has no assets**，不是 **no stub response**。
角色已经创建，不需要删号或修改国家/存档来解决资源缺失。

  历史上仅 country23 做过隔离原生加载/两个 prefab 实例化，不能代表全部国家画面验收。

## v1 的问题与 v2 的处理

v1 的全部 47 包通过结构和 HTTP 检查，但用户实机指出草地横条、远景竖缝。
仅验证文件可下载和组件完整，无法验证纹理在重复 UV 上的视觉连续性。

原网格的草地实际反复采样 256×128 小块；远景按 C/B/A/C 的顺序使用三段图集，
且水平方向由 UV 翻转。把三幅独立风景直接放入三个槽位会产生明显接缝。
v2 的图集编译器：

1. 保留原版草地像素及相应 BC3 压缩块，避免重复铺设时出现亮暗横带。
2. 从每国已创作远景的主视图编译连续、镜像闭合的全景，再分为相邻边缘共享像素的三段。
   天空重复条也处理为循环连续。前景对象的原版透明轮廓仍保留；
   远景透明轮廓与全景一起采样，避免沿用互不相同的旧分段蒙版。
3. 不改变场景网格或 UV。压缩回读后再次检查三处循环边界。

纪伊草地左右/上下边缘 RGB 平均差从约 12–29 降到约 2。
47 包均重新构建；46 个自制包原版草地像素完全一致，
各国压缩回读后的循环边缘平均差最大为 5.7088（0–255 量级）。
独立单测覆盖循环边缘、天空重复、草地原始压缩块和无效负载拒绝，3 项通过。

## 客户端缓存导致的旧画面

第一次只替换本地服务端包后，用户确实重启了游戏，但 Qt 缓存仍持有有效期 600 秒的旧资源。
旧缓存中可提取出完整 647,222 字节 UnityWeb 包，其 SHA-256 与 v1 完全一致；
因此当时截图不能作为 v2 的视觉结果。
备份并移走这一条本地缓存后，2026-11-18 00:04 网关实际记录下载 596,193 字节 v2，
随后用户确认接缝消失或明显改善。
独立本地启动器现在在新开本地客户端之前清理本地 PBM 下载缓存；
不清理其他资源、云端缓存或玩家数据。该启动器修复位于环境管理工作树。

## 本地验收与云端暂停

本地已将其余 45 个仍为 v1 的自制包按已知旧摘要替换为 v2；
纪伊此前已更新，37 国原版没有替换。每个输入、旧目标及新目标均核对摘要，
旧包和清单先备份；不匹配的目标不覆盖。
更新后 47 个 URL 全部完整 GET 和 SHA-256 一致，另有 23,198 个原有文件保持摘要不变。
不访问数据库，不改用户角色或进度，不重启用户游戏。

发布工具另有 9 项检查，覆盖不完整清单、输入篡改、未知既有内容拒绝、幂等、
HTTP 失败撤回新增、显式旧清单替换和回退、临时恢复文件清理。
默认不覆盖既有不同文件；`--baseline` 仅允许替换与旧清单 SHA-256/大小完全一致的自制包，
原版 37 国及未知内容仍禁止覆盖。低空间部署可用 `--no-persistent-backup`，
仅在操作期间使用临时恢复文件，成功或回退后清理；正式库不参与操作。

云端在暂停前已发布 24 自制＋37 国原版，共 25 国 v1。
暂停期间全量 47 国及 v2 均未上传；原 v1 全量归档已标为 UNAPPROVED。
用户随后要求提交 PR 并同步两端，明确要求云端不再积累额外备份；
本轮使用 Git 和本机既有原始资源保留版本，云端发布暂存验收后清理。
