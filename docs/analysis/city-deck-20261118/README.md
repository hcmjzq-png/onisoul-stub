# 本机石高与编成页

## 石高

旧实现一直读取初始值为 0 的 `player.kokudaka`，没有根据已放置建筑更新。
现在登录查询与保存时共用主城基础石高投影，完工、升级、进化、收纳和再部署后返回新值。
旧档自动重算，重试不会重复累加。建设中、库存及其他地图不计入主城；生产和内政编队不移除建筑的基础贡献。

单体插值来自原 `BuildingsTableAccessor.cs:617-642`：
`floor(float32(min + (level - 1) * float32((max - min) / (grade * 10 - 1))))`，
每步保留客户端 float32 舍入。复用现有的同式插值函数，原字段是 `grade/kokudakaMin/kokudakaMax`。
当前“汇总主城已完工建筑”是本服明确的兼容策略；原服全局汇总、武将技能及支城加成尚未还原。
不接入候选排行账本，也不把没有可信来源的加成写成原版规则。

原消费者 `UserStatus.cs:1820-1830` 读取可选根 `kokudaka`；
`PoliticFSMConstruction.cs:479`、`PoliticBuilding.cs:800/827/869/946/1287/2227/2425`、
`PoliticFSMBatchUpgrade.cs:80` 与 `PoliticFSMProduct.cs:1102` 会更新显示。
道路批量回包仍保持纯数字建筑索引，不加入会被当成建筑迭代的额外根字段。

缺少石高定义字段返回 `stub has no assets`；未知建筑引用或非法等级返回 `no stub response`，不悄悄算作 0。
测试用的最小建筑表补入同名原表字段；任务状态样本补入已有任务所需建筑原行及等级，不改变任务条件。

## 编成

本机 `common/getCharacters` 返回 7 名武将。19:00 重进后的运行时只读检查确认
`StatusList_/RefinedList_/statusDic_` 均为 7，`cardDic_` 为 0；编队面板已创建，
但 `nowPanel_` 与 `nowCards_` 都为空。停点在选择编队与卡图请求之前。

`deck/getDecks` 缺少原客户端强制读取的 `isEntrySiege`。
`DeckMake.setDeckCard` RVA 0x2F7010、布尔拆箱 0x2F7320（反编译 `DeckMake.cs:373`），
在 `setQuestPanel` 和卡片创建之前无条件执行 `(bool)deckTable["isEntrySiege"]`。
缺失值造成初始化中断，不能以 HTTP 200 或武将列表非空判断成功。
现在明确返回布尔 `false`，对应本服城战报名未接入、没有活动参战记录的范围。
该字段只属于查询回包，不放进玩家编队，不接受客户端覆盖，也不启用城战玩法。
这是回包契约缺项，不是空武将存档，也不能用 `stub has no assets` 概括。

部署查询契约修复后，用户确认武将列表出现。此时还有部分卡读取不完、切换立绘停留在同一张的问题：

- 初次补齐了 `chara1_09291/09294/09296/09298`，后续请求又暴露 `09292/09299` 两包 404，属于 **stub has no assets**。
- 六份兼容重建包都沿用了内部名 `CustomAssetBundle-3cf387e285da3c04aa84602c8e5fc364`，有多包加载冲突；早先的逐包成功不能证明共存成功。
- 六包改为各自唯一的内部名，完整序列化文件逐字节保持不变；保留所有贴图、名称和容器引用。构建器见 `tools/build_character_archive_fix.py`。
- 首次重开早于缓存清理，备份证明确有 `09294`（汤川直春）和 `09296` 的旧包缓存。定向备份、移除这六个资源的 Qt 磁盘缓存后，六项缓存内容 SHA 均与新包一致。随后完全退出重开，用户确认小卡与来回切换立绘均正常。

六包来自同名原始 TGA 对应的既有兼容重建，不是原 PC 包的原始字节。
每包含头像、小卡、卡面、战斗图共 4 个 Texture2D。已核对原画 SHA、容器名称、尺寸、像素误差和有界 LZMA 长度，
详见 [重建来源证据](asset-proof.json)；[v2 发布清单](character-archives-v2.json) 记录改名前后 SHA 和序列化文件不变的证据。
在经指纹校验的 PC WebPlayer 中同时保留六包，加载全部 24 张贴图，再于六包均驻留时复核每张的实际名称、类型和尺寸，
最后只释放探针自己的资源，见 [多包原生结果](native-retained-v2.json)。这是发布前对独立内部名的暂存文件测试，不释放游戏已持有的包。

本机发布新增两包、仅替换本轮先前发布的四包并备份，其他武将文件摘要保持不变。
六包经原游戏域名完整 GET 的字节与原生测试暂存文件完全一致；当前账号的七包、28 个预期贴图名均可解析。
原有 `chara1_00866` 包保持不变，原画和资源包不包含在 Git 中。
[旧版逐包 HTTP 结果](native-http.json) 仅作为首次四包的历史证据，不作为 v2 的加载或最终画面结论。
