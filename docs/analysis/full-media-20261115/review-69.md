## 已修复的问题

1. 原生结果原先只比较 ID、名称和尺寸 / 采样信息，同 ID 的不同包字节可能误复用旧结果。
   现在结果携带并验证 `output_sha256`；重新跑过全部 **12,162 包**，摘要与本地最终文件对应。
   报告额外核对 inventory 指纹、源解析失败、原始 PNG 的引擎指纹。
2. 转换进程在写文件后、清单 checkpoint 前中断，重跑会被现存输出阻止；清单输出丢失也会中止整个续跑。
   现在只复用完全一致的重建字节，丢失的输出重新进入转换，任何不同内容的已有文件均不覆盖。
   转换前还核对扫描时源对象指纹，避免来源变化后继续沿用旧 ID。

新增回归覆盖：旧摘要结果拒绝、乱序同名结果、丢失输出续跑、中断后同字节复用、
不同字节拒绝、发布时保留缓存中的 PC 原件、禁止贴图冒充建筑整包、HTTP 失败时仅回滚本次新增。

- 全部 **12,162 个 PC 包 + 1 个视频**发布到现有静态资源路由下的独立目录
  `/client/pc/jp/assets/converted/pr69/`，索引为该目录的 `index.json`。
- 只有原始 PS3 平台 10 的 AudioClip 且名称严格匹配 `vse...`，才候选补入原有
  `assets/vse/<UTF-16LE名称MD5>.unity3d` 地址。不能将 Texture2D 放入预期 GameObject 的建筑地址。
- 同名不同版本保留独立文件；Android、原始 PNG、场景贴图、标题音频 `title_L1_s` 等不猜测常规游戏地址。
- 上线前快照显示既有资源 **289 文件**。10,094 个常规语音候选中，144 个已有可返回文件须保留；
  预计只新增 9,950 个常规语音地址。正式数量以安装结果为准。
- 上传包 SHA-256 为
  `8d03d345dd26c576656ce88485f1379b36ed656da66a892b5c033cb6583dfedb`，
  服务器磁盘暂存已回读一致。暂存上传不等于已发布。

所有原有资源上线后再次核对 SHA-256；发布清单、保留原件清单和结果写入服务器私有备份目录。

## 批量发布的临时网关错误

#69 合并后，两次批量验收分别在不同文件遇到代理 HTTP 502；上传包已完整校验，
两次均自动回滚，289 个既有资源摘要保持不变。补充有限重试：HTTP GET 的
429 / 502 / 503 / 504 及传输中断最多尝试 3 次，记录实际重试数量；404 与 200 响应的
摘要错误立即失败。全量发布 HTTP 并发默认改为 4。Unity WWW 同样只对临时状态做有限重试。
此修复通过独立后续 PR 合并，不修改游戏程序或放宽文件摘要检查。

大批次验收随后暴露每次请求创建 urllib opener 的内存增长：服务器 100 次 GET 的
进程 RSS 从 24,464 KiB 增至 109,328 KiB。改为每个工作线程复用 opener 后，同样
100 次 GET 从 23,992 KiB 至 26,760 KiB。修复只限制校验工具内存，不变更下载内容。
发生终止前已写入的文件均须在恢复验收中重新校验，不能将进程被终止记为发布成功。
