# 本机测试与云端正式分离

本服运维设计，不是原服业务功能。原桌面快捷方式直开游戏，无法从入口辨认端口 80
当前连向哪台服务器。本轮增加环境身份校验、两个桌面入口和独立本机持久测试环境。
详细端口、配置及安装方式见 [运行说明](../../remote-development.md)。

本机使用独立 Python venv、免安装 MySQL 8.0.46 的 3307 端口、独立数据目录及账号，
只复制资源，不复制正式账号、密码哈希、会话或存档。客户端副本不带旧目录 Cache。
游戏保持原尺寸；身份标签复用网页既有标题和提示行，没有新增监控面板。
测试与启动不使用 Frida、Mono 注入或内存探针。

已验证：

- 完整本机隔离 MySQL 回归：676 项全部通过，无跳过；临时实例已正常关闭。
- 云端资源只读快照：23,197 文件 / 1,375,430,861 字节，逐文件 SHA-256 一致；
  复用 12,849 个本机内容摘要，只下载缺少的 10 文件；数据库未导出。
- 实际本机 hosts → gateway:80 → proxy:18082 → stub:18081：临时账号注册、登录、
  姓名/建号、重登、主城相关接口、编队与任务奖励冒烟通过，临时账号已清理。
- 上述全链路健康检查 20 次：中位 1.865 ms，范围 1.65–25.92 ms。
- 已有背景 25 国（24 自制 + 37 国原版）全部经本机 HTTP 下载与 SHA-256 校验。
  23 国的两个场景 prefab 在先前隔离原生加载中成功实例化；本轮没有再次启动游戏。
  其余 22 国背景未完成。此处仅为初始主城 variation 01，不涵盖扩城/支城。
- 对健康但角色/实例不匹配、PID 被复用及游戏打开时切服的拒绝行为已覆盖。
  实际 Windows venv 后台进程使用 base interpreter + `__PYVENV_LAUNCHER__`，
  保持 venv 包路径并直接记录真实监听进程，避免重定向子进程失去归属。

本机证据位于被 Git 忽略的 `work/environment-tests-20261117/`。
云端内部健康检查约 1 ms；本机直连云端曾出现 80 ms 到数秒及超时，
SSH 隧道对照也有波动，不能据此认定本机后端不稳定或宣称网络问题已修好。
代理/服务关闭小包 Nagle 延迟，网络抖动须在发布后另测。

云端发布与用户原客户端验收仍分别记录，不以 HTTP 成功代替完整游戏流程。
