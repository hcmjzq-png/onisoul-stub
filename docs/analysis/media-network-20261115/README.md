# 线上原生媒体批量校验的连接中断排查

本轮仅修改诊断工具，不修改正式客户端、游戏接口或资源文件。
测试链路为客户端 → hosts → 本机 80 转发 → 云端 proxy80 → stub。

## 已确认的条件

- 旧驱动启动时向 8 个 HTTP 工作线程一次提交全部 12,162 次预检；
  Unity 另有 4 个 WWW 下载槽位，`--queue-size` 只约束原生待处理队列。
  原生加载停顿时，HTTP 预检仍持续下载，造成重复流量竞争。
- 原生单次加载固定 20 秒，只重试含 429 / 502 / 503 / 504 的错误；
  实际引擎也会只返回 `Failed downloading URL`，旧工具直接记失败。
- 自建后台 QA 客户端的 `Application.runInBackground` 实测已为 true。
- 不重试的 400 次 GET 对照：云端直连 386 成功 / 14 超时，本机现有 80 转发
  380 成功 / 20 失败，隔离转发 388 成功 / 12 超时。每组并发为 4，socket 超时
  10 秒，成功响应均匹配摘要；部分测试与原生抽测重叠，不能据此归咎某个代理。
  证据位于忽略目录 `work/network72/matrix-*.json`。

## 修复和验证

- HTTP 预检改为有界窗口，默认最多 2 个下载且只提前 2 项；Unity 默认并发 2，
  待处理与活动任务合计最多 4 项。等待预检时仍轮询原生状态、保存进度。
- 下载单次超时可配置，默认 60 秒；每 URL 最多 5 次尝试，有限退避并记录原生
  重试原因。播放另按音频时长计时；解码失败、缺少对象、内部包名冲突不当作网络重试。
- HTTP 预检仍完整 GET 并计算 SHA-256；404 和摘要不符立即失败。
  原生结果同时核对 URL、输出摘要及解码后的类型、尺寸或音频元数据。
  原生 WWW 的摘要证据来自独立完整 GET，不声称 WWW 直接回读了原始包字节。
- 修复后线上抽测 128 / 128 原生加载通过。
- 本地故障注入同时覆盖断连、慢响应与 503，3 / 3 最终加载成功；
  原生结果记录了超时及 `Failed downloading` 重试。该项不是线上通过数量。
- Windows 回归 647 项：615 通过，32 跳过。

完整 12,162 包的线上原生验收将在部署同版工具后执行，尚不能以抽测代替全量。

### 全量开始后的预检等待修复

PR #72 已合并部署至 `0941724816e5b075351678e8022885b777359c36`。
服务器 647 项回归通过（35 项跳过），部署前后 PC 目录 23,213 个文件摘要一致，
原始资源基线 289 / 289 保持原摘要，5 份现有玩家存档未变，stub / proxy 未重启。
这个目录计数还包含表等文件，不能当成独立媒体数量。

带本次独立查询参数的全量运行前 200 包原生加载成功、无原生重试；其中 9 包
HTTP 预检重试。旧窗口仍按序等待，一个 60 秒的慢预检会阻挡已完成的后续任务。
因此停止该次运行，补上按完成顺序投递（仍按 ID 校验，不跳过任务），并将完整 GET
的 socket 超时独立为 10 秒，原生单次加载仍为 60 秒。进度每 10 秒原子保存。

另以两个 socket 分别使用默认路由和指定有线网卡，同时对照 60 个资源：默认路由
54 成功 / 6 失败，指定网卡 59 成功 / 1 失败；两者均出现响应体读取超时，默认路由
另有 4 次连接被拒绝。样本不足以认定隧道是唯一原因；未改动系统路由、VPN、hosts
或用户已有的本机 80 转发。证据为 `work/network72/interface-matrix.json`。

补充修复后的 Windows 回归 648 项：616 通过，32 跳过。
同版再测 128 个全新查询参数 URL：128 / 128 原生加载通过，用时 75.797 秒。

### 网络中断后的断点续跑

PR #73 合并部署至 `55d623939581a1e59c049e6808886406745cf48b`，服务器 648 项回归通过
（35 项跳过），资源摘要、5 份存档保持不变。正式全量使用 4 个原生槽位、3 个 HTTP
预检线程，原生排队和活动合计最多 6 项。独立查询参数保留在完整清单中。

该轮完成 4,708 包后，一个 HTTP 预检在读取响应头时耗尽 5 次重试，驱动退出；
已完成包没有原生最终失败。前述运行不算全量通过。

增加 `--resume-from <旧结果.json>`：要求完整清单、引擎、原生脚本指纹完全一致，
再逐项核对已成功结果的唯一 ID、URL、输出摘要、类型和解码元数据。只有这些成功项
可复用，其他项目继续测试。旧失败记录及旧文件摘要放入 `previous_attempts`，
原始结果文件保留。清单变化、未知 / 重复 ID、解码元数据不符会拒绝续跑；新增要求
静音播放时，旧的只解码结果也不会代替播放。预检终止错误现包含具体 ID 和 URL。

本次不稳定链路的续跑将 HTTP 尝试上限显式设为 8，保持有限退避、完整 GET 摘要验证，
不放宽 404 或摘要错误。Windows 回归 651 项：619 通过，32 跳过。
人工构造仅保留 64 个合法成功项的检查点，复用这 64 项后继续其余 64 项，最终
128 / 128 校验通过；该项用于验证续跑流程，不计入新增线上资源数量。

## 与国家选择问题的区别

另一个聊天的国家图检查为 20 国 HTTP 200、27 国 404；18 个已存在的图片包
共用内部文件名，真实游戏日志出现重复加载冲突，失败后共享 `BushoTrans` 锁未释放。
这是国家选择卡住的直接证据；27 国缺图属于 **stub has no assets**，没有证据认定
地图点击卡住是 **no stub response**。

本轮 12,162 个转换包有 11,902 个不同内部文件名；共享文件名的包具有相同输出摘要，
不存在内部文件名相同但内容不同的分组。国家选择的图片冲突修复不包含在本轮网络探针修改中。

所有既有 PC 原版及已转换资源保留，不通过覆盖资源缓解下载失败。
