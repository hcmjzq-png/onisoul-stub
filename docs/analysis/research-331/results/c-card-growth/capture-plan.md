# C 串行运行验收计划

由总集成对话独占 Unity3.5.7；本组未启动客户端。使用隔离账号和可审核的真实库存来源，
不改现有玩家。游戏原始尺寸保持；监控面板与游戏等大对齐。
记录客户端 → hosts → proxy80 → stub 四层；**本机**与**局域网**各自保存路由/
地址配置记录，不能相互冒充。请求/响应及存档去 token/凭据。

## 道具闭环及身份适配

前提：已审核传输适配可为同一次用户点击在十次 WWW 尝试中保留相同身份；下一次相同
点击不同身份。无此适配，不开放候选路由。拥有未保护/未编队武将、普通石和 150 credit。

1. 正常 getPotions、common/getCharacters 记初始值。购买 shop0700013：应扣150 credit，
   铃+1；确认原普通商店回调刷新余额。使用五颗 potion0000416：三项总值/Add各+50，石-5。
2. 用一颗拆除铃：总值恢复，Add清零；三类分别40+10石各一颗；铃0在响应中出现，
   重开 getPotions 则不再列铃。确认 addItems 是显示增量、changeItems 是余额。
3. 一次返回前模拟丢包；相同身份重试必须 errorReason、存档不变，不再进成功回调。
   记录原错误框、重新登录后的权威余额。一次成功后再次新点击能正常使用。
4. 保护、头像、六种编队、仓库引用、资源不足、超cap、拆除余数分别记录完整失败及
   前后存档哈希；这是有限支持策略，不拿 stub 失败证明原服也这样拒绝。

## 能区分尚未证明规则的原服资料/旧记录

只用模拟服抓包可验兼容性，不能证明原服经济公式。下列需原服旧流量、同期完整视频或
额外原资产，不能从本服自造结果归纳：

- 剩余空间小于一颗/五颗石时：请求 count、前后全部总值/Add、potion余额；区分截断、
  少用、全耗和拒绝。神石某一项先满也须分开观察。
- 拆除 Add 不为10倍数：逐项 addItems、changeItems、原 Add；区分损失余数或其他转换。
- 强化：相同素材的 materialPoint/属性阵营/等级、活动系数、rank/经验/资源；不要由一次
  大成功反推概率。进化需完整 characterData/learningSkills；继承需失败保护与 inheritPoint。
- setSkillSlot：付款档位、目标grade/原技能/新技能所有字段、余额及足够样本；区分
  全表权重、等级/种族过滤、固有技能保护、重复重抽。样本仍须明确置信范围。
- 九宫格：记录三项完整响应、活动版本/日期、九格商品/奖励/费用，追踪同卡经任务、
  鬼签、挂卖、特殊抽取获得的点亮差异；出售后/仓库中是否保持资格；reward字符串与
  result实际值。一次抽取丢响应与一次领奖丢响应分别观察。前提没有满足时保持关闭。

捕获缺文件或无法加载标 `stub has no assets`；接口规则、坏引用、未发状态标
`no stub response`。不把客户端动画的伪随机当服务端抽样证据。
