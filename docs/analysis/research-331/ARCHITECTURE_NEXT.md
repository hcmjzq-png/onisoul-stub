## 存储和服务边界

1. **个人档案先保持兼容。** 保留 players.state_json 和现有 revision/CAS。已有资源、任务进度、物品不因升级重置。只有明确的查询、约束或性能需求才拆对应字段，不一次性改造全部存档。
2. **跨账号变化同一事务。** 双边好友、买卖双方、共享记录与收据必须整笔提交。应用层进程锁不能替代数据库并发控制。I 的 shared_records 是过渡存储能力，不能将其存在当成拍卖、排行或战争已经实现。
3. **共享业务逐项定义模型。** 每个流程明确记录所有者、标识、状态转换、唯一约束、查询方式和保留策略。交易订单/托管、奖励发行/领取、活动/结算、排名投影优先按实际需要设计；需要索引或数据库约束时再使用专用表。这里均为内部设计方向，不是新发现的原服表名/字段。
4. **业务和网络分离。** 原协议适配负责解析和回包；业务层负责资格、费用、收益和状态转换；状态层统一事务与持久化；原表层提供规则数据。沿用现有模块逐步实现，资源服务、proxy80 和客户端配置无需随之重写。
5. **时间也要能恢复。** 生产/冷却/活动截止信息持久化，业务可注入测试时钟。重启后依据存档恢复；有原始语义依据时可在访问时结算。只有确需全局定时结算或可靠异步通知时再增加后台任务、同事务待发送记录及消费者，不能把内存计时器当完成。

## I 与业务组的接入契约

- 以审核后的 I 接口为唯一实现；D/E/F/G 不复制自己的数据库适配器，不在业务代码拼 SQL。
- #52 当前约定为：全部玩家 ID 排序加锁，然后全部共享键排序加锁。不要沿用旧文档“先锁挂牌后锁玩家”的相反顺序。提前声明完整集合；必须预读才能发现集合时，锁内重新核对并在集合变化时整笔回滚。
- 事务内只修改该事务交付的对象，不嵌套 state.load/save/atomic，不发网络请求或通知。提交成功后才发送成功回包。需可靠通知时，与业务变化一起记录待发事项；#52 尚未实现发送器。
- 锁超时/死锁回滚后重新读档、重新检查，再作有界重试。COMMIT 确认丢失可能已落库，必须按持久操作身份查结果，不可盲目重复扣发。官方建议使用一致锁序并处理事务重试，见 [MySQL deadlock handling](https://dev.mysql.com/doc/refman/8.4/en/innodb-deadlocks-handling.html)。
- 操作身份要来自真实请求/流程可辨识的上下文。不能每次随机生成 ID 便宣称防重，也不能永久用参数哈希把两次合法相同操作合并。原协议无法辨识时，列出缺口并做定向客户端采集。
- 数据库只执行一次仍不足以证明客户端正确：核对原消费者是赋值还是增量更新，防止重放成功回包让客户端二次扣款/加奖。资源刷新只能使用已有、已证协议。
- #52 的 256 条事务键上限不是全服扫描方案。排行聚合需要独立的分页/事件消费、一致性水位及发布策略，不把大集合拆成多次提交后宣称原子。

## 集成、发布与回退顺序

1. 汇总对话固定九个 PR 的提交 SHA，审核代码和证据，再在独立集成分支处理公共补丁。旧基线 integration.patch 需按最终代码逐段适配，不能顺序盲套；各组自己的工作树不重置。
2. 先复核 I，使用独立 MySQL 测试库验证旧单玩家保存、跨账号竞争、第二笔写入失败、提交失败、提交结果不明和重登。核对实际服务器 MySQL 版本，不能用提交者本地 8.4.13 测试替代版本兼容检查。
3. 接 E 好友首个流程，随后按完成度接 C/H、A/B；D/F/G 可并行研究及组件实现，正式开放按来源和事务依赖决定。每次只接证据充分的范围。
4. 检查正常注册器，再沿客户端→hosts→proxy80→stub 做 HTTP 和串行 Unity 验收；确认重启、重登、重复请求和通知显示。各组不并发操控同一个客户端。
5. 按 CONTRIBUTING.md 由 owner 合并。发布时记录代码 SHA、配置、原表清单与数据库迁移版本；先备份并验证恢复流程，再执行兼容旧代码的扩展式迁移。不得在请求路径自动跑 DDL。
6. MySQL 部分 DDL 会隐式提交，不能承诺用 ROLLBACK 撤销建表/改表，见 [MySQL implicit commits](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html)。代码回退不等于撤销已发生的玩家交易；停止相关新写入后按账本核对，不直接恢复旧库覆盖后续合法进度。

每次验收分别报告：证据缺口减少、完整可用流程、正式注册变化、Unity 通过项、已部署版本。主分支、候选分支和服务器计数分开。
下一步交付是 I/E 首批集成审核及缺陷修复，不重新按 331 个入口平均分配“补成功回包”。
