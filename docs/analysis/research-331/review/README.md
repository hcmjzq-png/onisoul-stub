## 汇总发现与修正

1. **新账号定时查询会打断创建流程。** 原 SessionKeeper.cs:176-199 在收到 token 后立即开启 PeriodicRounder，角色未创建也会调用。E 原通知逻辑要求 created，因而把该正常阶段返回为错误。现在未创建角色只返回原定时查询字段，不伪造社交计数、不写档；真实 SQL + HTTP 回归覆盖。
2. **好友写库只执行一次，但成功回包会重复改变客户端计数。** 原 FriendConfirmationWindow.cs:195-299 在成功后增减申请/好友计数。E 对重复发送、接受、取消、解除仍返回 result=true。现在无实际状态转换时返回原协议 result=false/detail，保留数据库状态；并发重复请求仅一次成功。丢首次成功回包仍需重新查询/重登，不能宣称无感恢复；跨全新申请周期的迟到请求依然无法仅按原字段辨认。
3. **F 与 I 的锁顺序说明冲突。** F 原稿写活动→玩家，I 实现是全部玩家排序→全部共享键排序。已修正 F 接入文档与代码注释，统一服从 I；本次没有把 F 测试存储改称生产适配器。
4. **旧契约测试把禁用接口当成成功接口。** 接入 I 的 Registry 拒绝后，旧测试仍要求 debug 的 enable/score 等成功字段。已改为验证拒绝及 errorReason，正常成功契约继续校验。B 的测试改为检验正常注册器，避免对已集成代码重复应用历史补丁。

资源错误仍分开：文件/表加载缺失为 `stub has no assets`；缺实现、坏引用或缺可信业务状态为 `no stub response`。
用户指出的九项旧 AI 实现不作为来源。本次收件箱限定原 InboxReader/InboxResolveWorker 消费协议与四资源，不恢复伪造邮件网页或任意奖励。
