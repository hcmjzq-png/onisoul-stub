## 状态怎么读

- **已接入**：正常 `build_registry()` 确实使用该处理器。仍须看支持范围和验收列。
- **部分接入**：一个功能只开放了明确的子集，例如查询药品不等于能使用药品。
- **候选未接入**：代码或测试存在，但正常游戏请求仍走占位处理器。
- **占位**：只有默认回包，或明确拒绝未实现操作；不视为业务成功。
- **本机实现**：例如 DPAPI 保存助手，运行在玩家电脑，不能算成纯服务端功能。
- **禁用**：管理/调试入口刻意关闭，不列为待开放的正常玩法。

“自动回归”“真实 SQL/HTTP”“原生加载”“Unity 操作”分别记证据，不相互替代。
本机与局域网各自验收；原生包可加载不等于玩法或画面完整。
服务端处理器、本机助手、下发客户端补丁和离线资源转换分别注明；
例如 #76 的国家预览锁是客户端兼容修复，不计作新增服务端业务。
原版可证实的规则、本服内部设计和兼容补丁必须分别标注，旧 AI 功能不能充当原版证据。
资源缺失写 **stub has no assets**，缺业务实现写 **no stub response**；
回包不兼容和客户端状态问题另记原因，不强行塞进这两类。

S01.3/4 → S02.1 → S03.1/2/3 → S04.2。

## 后续每个任务怎样交付

每次任务指向一个编号及其依赖，例如“S05.2 一种田地生产结算”，并写清：

1. 用户如何触发、前置资格和预期结果；本次支持/不支持的范围。
2. 原客户端、原表或可靠外部资料证据；不确定的规则及定向取证办法。
3. 涉及的真实接口、代码位置、存档变化和资源依赖；内部设计不得称为原服字段。
4. 一致性和重试验证；正常操作、失败分支、退出重登的实际结果。
5. PR、合并提交、发布项/备份、客户端验收结果和剩余问题。

合并、部署、验收分别更新，只有对应支持范围全部通过才标“验收通过”。
每个子项由一个聊天负责，跨系统接口列依赖；多人不同时改同一接线点或存档结构。
先保持当前分层单体代码，用模块边界组织工作；不为管理拆分额外引入微服务或更换数据库。

## 路由明细与更新方式

[endpoints.tsv](endpoints.tsv) 给 402 个路由各分配一个主要系统；跨系统依赖在子项台账描述。
它覆盖注册器的全部入口，不覆盖登录 HTML、静态资源、SQL 或本机工具等非 RPC 能力。
[routes.json](routes.json) 是自动汇总：80 个专用处理器，273 个默认回包、17 个明确失败、32 个禁用入口。
后面三类合计旧口径的 322 个占位。其中战争哨兵、空活动、诊断日志等专用处理器也不算完整玩法。

安装正常服务端依赖后，在仓库根目录运行（只读注册器，不调用接口、不连接数据库）：

```powershell
python tools/export_system_status.py --output docs/project-status
```

每次功能 PR 更新相关子项和证据；改变接线时重导路由表。旧分析目录保留为历史快照，
有新验收时链接最新记录，不继续引用早期“未上线/未验收”的状态作为当前结论。
本台账中的“已接入”按上述代码基线核对；发布和真机结论按各链接的限定记录核对。
